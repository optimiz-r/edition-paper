# edition-paper audit · 2026-11-23

Audited `origin/main` at `e97ada55fdcec2f1b9412bef6e6301f861be6399` on Ubuntu 26.04.1. The packed tarball matched npm's published `1.0.0` integrity. The fixes are independent draft PRs against that commit.

## Decisions and first-run blockers

- **First failure can disclose the source list.** Run the packed CLI with a synthetic setup, `--no-print`, and `--url http://127.0.0.1:1`. The connection-refused diagnostic on main included the encoded setup. Failed image URLs and custom origins could also disclose query parameters or user information in logs. Decide whether to prioritize this fix before more users schedule the tool. [PR #2](https://github.com/optimiz-r/edition-paper/pull/2)
- **A clean install ran a browser runtime that differed from the test environment.** Compare `npm ci` on main against `npm install ./edition-paper-1.0.0.tgz` in an empty directory. They selected Playwright Core `1.64.1` and `1.65.1`, respectively. When explicit Chromium was absent, the CLI also suggested installing Chrome, which that flag skips. The draft pins `1.64.1` and fixes the install hint. I chose the lockfile version and verified it with the downloaded Chromium. [PR #3](https://github.com/optimiz-r/edition-paper/pull/3)
- **A large copied setup can fail before Node starts.** A valid synthetic setup of `133348` bytes triggered `E2BIG` with no CLI status. The decoder accepts up to `262144` bytes. Decide whether a future interface should accept setup from a file or stdin. A CLI diagnostic cannot run when the OS rejects the argument.
- **The print step can hang after a successful first render.** A test double for `lpr` that stalled beyond its budget returned success on main once it eventually exited. The draft gives the child the remaining five-minute budget and retains the PDF and existing print-failure path. A timed-out submission may require checking the printer queue. [PR #4](https://github.com/optimiz-r/edition-paper/pull/4)
- **An attempted macOS reinstall can drop a working schedule.** With a prior fake installation in a temporary home, fail both replacement `launchctl bootstrap` calls. Main removed the old plist and runner. The draft keeps them until the new agent loads and restores them after a failure. Real launchd behavior still needs macOS validation. [PR #6](https://github.com/optimiz-r/edition-paper/pull/6)

## Verification

### Package and arguments

- `npm pack` produced `17071` compressed bytes, `46613` unpacked bytes, and 13 entries. The allowlist contained the CLI, runtime modules, README, license, and manifest. The executable was mode `0755`. Tests, fixtures, dependency files, and local artifacts were excluded. The registry and local tarball had the same integrity. A clean public `npx --yes edition-paper --version` printed `1.0.0`.
- The tarball install passed `--help`, `--version`, and a loopback A4 render on Node `20.20.2`, `22.23.3`, `24.13.0`, and `26.13.0`. Node 20 was fetched into a temporary directory to check the declared minimum. The flag-name comparison printed `Help and README name the same 12 flag spellings. Tar allowlist and executable mode passed.` The declared bin, ESM type, and Node floor agree with these runs.
- The packed CLI printed `Missing --setup. Open edition.cafe/paper and use "Copy 8am command".` and exited 1 when invoked without arguments. I exercised missing, empty, duplicated, invalid, and control-character inputs, plus valid Unicode and shell metacharacters. Boolean flags reject attached values. The CLI takes a base64url JSON argument and has no separate config-file discovery or config-file permission cases. The table-driven setup tests cover the parser that exists in this package.
- A directory outside the fixture working directory, a path with spaces and Unicode, and a literal `~/Unicode 紙` worked. A file used as `--out` and a read-only output directory exited 1 with `EEXIST: file already exists` and `EACCES: permission denied`, respectively. The documented `--out` value is a directory.

### Feeds, network, and output

- All paper, feed, and image requests used loopback fixtures, or a forced local resolver failure. The mock page issued requests for redirects, 503, 429, malformed XML and JSON, HTML, a 2 MiB response, a timed-out fetch, and an ISO-8859-1 response. It put failure labels beside surviving content. The packed CLI saved the partial PDF and printed `Printing without 1 picture that never loaded:` for the broken image. The real feed parser, limits, retries, and content sanitization belong to the app. The fixture's behavior is evidence about the CLI's render and print boundary.
- The empty fixture saved a PDF, exited 1, and logged `No stories rendered; not sending to the printer.` A plain HTTP 429 reproduced `The page was still composing after 90s; printing what settled.` The fixed CLI saved the error PDF, exited 1, and logged `No stories rendered; not sending to the printer. Edition returned HTTP 429.`
- A synthetic DNS failure after the fix printed `page.goto: net::ERR_NAME_NOT_RESOLVED at http://browser-audit.invalid/paper` without the setup query. A loopback server that never wrote a response exited 1 after 64 seconds wall time and printed `page.goto: Timeout 60000ms exceeded.`
- `pdfinfo` reported `Pages: 1` and `Page size: 595.92 x 842.88 pts (A4)`. With fixture CSS specifying an 18 mm page margin, `pdftotext -bbox` put the first word at about 57 pt from the left, including the browser's default body margin. All 50 word boxes fit the page width. The generated PDF retained a long URL, Arabic, and an emoji. `pdffonts` found embedded Liberation Sans, DejaVu Sans, and Noto Color Emoji from this Linux host. Actual Edition CSS, image availability, and font availability on fresh hosts remain unverified.
- A Google Chrome 157 render and a separately downloaded Playwright Chromium render both passed with loopback pages. The documented Chromium install placed Chrome for Testing, Headless Shell, and FFmpeg in an isolated browser cache of about 681 MiB on this host.

### Scheduling and platform behavior

- `/bin/sh -n` accepted the generated script. `crontab -n` printed `The syntax of the crontab file was successfully checked.` I ran the command portion directly with a bare `/bin` PATH, no TTY, `LANG=C`, `TZ=Pacific/Auckland`, and a temporary home containing only test artifacts. The script found the intended Node/npm path, exited 0, redirected output to `edition-paper.log`, and produced the next local day's filename while UTC was still on the audit date. The generated Linux hint itself exited 1, as documented by the existing tests.
- Ubuntu's installed `crontab(5)` says cron supplies `HOME`. The recipe depends on that value for the script and log. `env -i` with a minimal PATH ran `--version` without `HOME`, and the parser used the account home for the default output directory. A simulated New York fall-back hour produced the same local date for both 01:30 instants. Ubuntu's `cron(8)` describes special handling for clock shifts of less than three hours. Sleep and wake catch-up was not exercised.
- Python's `plistlib` parsed the golden agent as `com.edition.paper {'Hour': 7, 'Minute': 5}`, with an absolute Node path and matching stdout and stderr paths. The Linux tests used a fake `launchctl` for install, replace, rollback, and uninstall. The Windows test generated a PDF-only Task Scheduler recipe and escaped literal percent characters. I did not run `.cmd` or `npx.cmd` on Windows.
- A fake `lpr` received exactly three literal argv values for a named printer and a PDF path containing spaces and Unicode. With `lpr` absent the CLI exited 1 and retained the PDF, reporting `Printing failed (is a printer set up? lpstat -p lists them).` Neither a printer nor a scheduler service was used.

### Dependencies and regression gates

- `npm audit` printed `found 0 vulnerabilities` for the repo lockfile, the fresh tarball install, and the pinned install. There was one runtime dependency and no transitive runtime dependencies or install hooks. The fresh install occupied `14019002` file bytes in `node_modules`. Playwright Core `1.64.1` was the only patch in the existing locked minor range, so I made no version bump.

Explicit baseline attempts printed `Missing script: "lint"` and `Missing script: "build"`. The package gate substituted source syntax checking and packaging. The publish-only live-link check was skipped.
- All seven patches applied cleanly together in a detached temporary worktree. The combined suite printed `pass 66` and `fail 0` on Node 20 and Node 26. All changes remain in draft PRs.

## Compatibility decisions for a future version

1. Offer setup from a file or stdin to avoid OS argument limits. Consider an alternative to URL query transport to limit exposure to server access logs. These require a new input interface and app support.
2. Decide whether to reject empty `--out`, duplicate flags, a path or credentials in `--url`, and invalid channel entries. Tightening validation would change accepted commands or require the CLI to share the app's source schema.
3. Decide which HTTP failures should fail immediately, and whether an empty but valid edition should be a successful PDF-only run. Existing callers can depend on the saved diagnostic PDF and exit 1. Also decide whether to retain the multi-line browser instructions and platform recipes on stderr.
4. Make Letter and reproducible PDFs opt-in. The current interface fixes A4 and relies on page CSS, system fonts, and browser metadata.
5. Define overlap and catch-up behavior explicitly before introducing single-run enforcement or an alternative scheduler. In particular, decide what a skipped run should log and return. Keep dependency and browser installation under the user's control.

## Native verification checklist

- [ ] On macOS, lint the generated agent with `plutil -lint`. Try a fresh install and a failed replacement in a disposable user session. Confirm the previous job reloads, the new plist is mode `0600`, and unattended execution can find Node and Chromium.
- [ ] On macOS, verify wake from sleep versus shutdown, DST behavior, custom output paths, and the Documents-folder permission prompt. Confirm log capture and duplicate prevention with real launchd.
- [ ] On a disposable Linux environment, confirm missed schedules on suspend, resume, and a DST change with the cron implementation readers actually use.
- [ ] On Windows, run the generated `.cmd` through Task Scheduler with spaces, non-ASCII, percent signs, CRLF line endings, and a bare PATH. Confirm drive-letter and home-relative paths, quoting, and PDF-only behavior with the system's `npx.cmd`.
- [ ] With an explicitly chosen test printer, verify default and named queues, submission timeout handling, physical margins, duplex settings, and paper size. The Linux audit sent no real print jobs.
- [ ] Verify the deployed app's feed parsing, per-feed limits and error labels, feed markup sanitization, external resources, and print CSS with recorded fixtures owned by that project.
